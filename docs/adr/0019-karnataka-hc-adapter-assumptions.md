# 0019. Karnataka HC adapter: layout assumptions and how H13 retires them

## Status

Proposed

## Date

2026-10-22

## Context

The Karnataka High Court adapter `in.ka.karnataka-hc.bengaluru` (#37, part 1 #404) parses cause lists and orders the lawyer supplies for the Principal Bench at Bengaluru (A1, `packages/db/src/seed/forum-catalogue/karnataka-hc.ts`). It follows the framework rules of [ADR 0015](0015-court-adapter-framework.md): no network, access modes from the registry, court differences in versioned config.

The research could not open an output cause list, the sitting lists or the official case-type table (`casetypes.pdf`). The legacy NIC host refused every connection ([research/raw/09](../../research/raw/09-bengaluru-karnataka-court-ecosystem.md), fetch caveats and §6). The column layout, heading names, Bar Registration Number (BRN) format and numbering are therefore assumptions. Each one is captured as config or as a tolerant rule, tested on synthetic FICTIONAL fixtures, and retired by H13 ([#119](https://github.com/RapierCraftStudios/causedeck/issues/119): 30+ lawyer-supplied lists and 50+ orders per HC).

## Decision drivers

- Wrong guesses must degrade (unmapped heading, unknown type, diagnostic), never throw or invent data.
- Every assumption has to be changeable as an `adapter_version` config, without a code release.
- The adapter never fetches a URL, and none of the court's pages is read automatically.

## Considered options

| Option                                                 | Verdict  | Reason                                                                   |
| ------------------------------------------------------ | -------- | ------------------------------------------------------------------------ |
| Ship assumptions as config with tolerant parsing       | Chosen   | Matches ADR 0015; real fixtures can retire each one with a config change |
| Wait for real fixtures before building the adapter     | Rejected | Blocks the A1 forum; H13 needs a lawyer and has no date                  |
| Retrieve sample lists from the court site to calibrate | Rejected | Fetching is out of scope for A1 and forbidden by the no-network lint     |

## Decision

The adapter shipped version 1.0.0 (`packages/adapters/src/karnataka-hc/`, `adapter_version` row in migration 0049). Version 1.1.0 (migration 0051, #405) adds the cause-list parsers and seeds the stage map from practitioner usage. It ships with these assumptions, each listed with the H13 check that retires it:

Real-fixture results (`ADAPTER_PRIVATE_FIXTURES_DIR`) are reported separately and are not required for merge. The committed fixtures are FICTIONAL and synthetic (#408). Deep links open the court's cause-list, case-status and judgment pages in a new window from the forum catalogue; the adapter reads none of them.

The 1.0.0 row, and the 1.1.0 row that retires it, were inserted active by migrations with `fixtures_digest` null, before any KHC golden fixtures were committed. The fixtures came with #408 and leave the 1.1.0 row as it is; every later version goes through `activateAdapterVersion` and its golden gate.

### Synthetic fixtures and golden metrics (#408)

`packages/adapters/fixtures/in.ka.karnataka-hc.bengaluru/` holds 12 committed cause lists, 12 orders and 4 FR / scrutiny-objection notices, all FICTIONAL. The lists are 11 saved HTML pages and one consolidated column PDF: a daily Bengaluru list with 3 halls and 2 lists each, advance, supplementary, Dharwad-style 100xxx numbers, no advocate columns, heading variants, an "Orders (registry objections)" list, header cells and stage headings reflowed over two lines, broken HTML, a sitting-list page (`not_a_cause_list`, zero rows) and an empty list. The orders cover the `KHC`, `KHC-D` and `-DB` citations, an interim order with a relative date, an absolute call-on date, a reserved order, a common order, a decoy date, no next date, a writ category, RFA and RSA, a 22-page order and a scrutiny-objection order. `test:golden` checks every one against its expected file. The broken-HTML input is excluded from Prettier, so its bytes stay malformed.

`packages/adapters/src/karnataka-hc/synthetic/generate.ts` builds seeded documents in the grammar above: HTML list pages, column PDFs (`writeSyntheticColumnPdf`, each cell at its column's x with up to 3 pt of jitter, wrapped cells on continuation lines), orders and notices, each with its truth. `pnpm --filter @causedeck/adapters gen:fixtures --adapter karnataka --seed 7` writes 32 lists (8 PDFs), 50 orders and 10 notices to the git-ignored `packages/adapters/fixtures/generated/`. `src/karnataka-hc/generated-metrics.test.ts` gates them in `test:metrics`, run by the CI "Adapter golden metrics (generated)" step: row precision >= 99.5%, recall >= 95%, order-date accuracy >= 98% and zero invented dates. A decoy earlier-order date is printed but left out of the truth, so emitting it counts as invented. A wrapped case-number cell in an HTML row has no verbatim anchor (A12), so the generator and fixtures keep case numbers on one line there.

## Consequences

- Positive: the A1 forum has a registered adapter and config now. Each assumption is one config value or one rule that H13 can retire.
- Negative: until H13, parse quality on real lists is unknown. Unmapped headings, unknown types and missing advocate columns show up as diagnostics, not as data.

## Revisit when

- H13 (#119) delivers real Karnataka HC lists and orders.
- The Dharwad or Kalaburagi Bench is enabled (v2), which needs its own adapter config.
- Display-board access is legally cleared and `stageCodeLegend` gets content.
