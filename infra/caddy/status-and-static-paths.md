# Status and static site paths (refs #98 Caddy, #99 Terraform; part of #772)

The Caddy (#98) and Terraform (#99) configs are not in this branch yet. When they land, they must
honour these paths. Everything here is public, tenant-free and cookie-free.

| Path                                                | Served by                          | Requirement                                                                                                                                               |
| --------------------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/status/`, `/status/history/`                      | Cloudflare Pages (static export)   | Static HTML with the headers in `apps/site/public/_headers`. No origin round trip.                                                                        |
| `/status/feed.xml`, `/status/atom.xml`              | Cloudflare Pages (built at deploy) | Content types `application/xml`; regenerated by each site build.                                                                                          |
| `/status/status.json` (`status/status.json` object) | Object storage, same origin        | Public read, `Cache-Control: no-cache` or `max-age<=30`, CORS not needed when same origin. Written by the worker every 3 minutes (`REPUBLISH_AFTER_SEC`). |
| `/_next/static/*`                                   | Cloudflare Pages                   | `Cache-Control: public, max-age=31536000, immutable` (already in `_headers`).                                                                             |

Rules for the edge config:

- The status page must stay reachable when the application is down: route `/status*` to Pages or
  the object store, never through the app upstream, and exclude it from the app's rate-limit and WAF
  challenge rules (a challenge page would make the page unreadable during an incident).
- `status.json` is fetched by the browser. Same origin needs no CSP change; an absolute
  `NEXT_PUBLIC_STATUS_URL` adds its origin to `connect-src` (`apps/site/scripts/write-headers.ts`).
- Do not cache `status.json` at the CDN longer than 30 s. The page treats a snapshot older than
  300 s (`STALE_AFTER_SEC`) as stale and says so.
- Security headers for the static site come from `_headers`; Caddy must not rewrite the CSP for these
  paths.
- Lighthouse (mobile, score >= 95) and the Playwright status spec (`e2e/site/status.spec.ts`) run
  against the exported site in CI, not against this edge config.
